# Калории

[Открыть приложение](https://kolpakov-uz.github.io/kalorii/)

Статическое приложение для дневника питания. Интерфейс находится в `index.html`, браузерные уведомления — в `sw.js`, серверная логика Gemini и push-уведомлений — в `worker/index.js`.

## Публикация

GitHub Pages автоматически публикует корень ветки `main`. Worker `kalorii-ai` публикуется через Wrangler с конфигурацией `worker/wrangler.jsonc`.

На настроенном компьютере из папки репозитория:

```powershell
npm.cmd --prefix worker ci
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/publish.ps1 -CheckOnly
```

После проверки и коммита изменений:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/publish.ps1
```

Скрипт проверяет исходники, собирает Worker без публикации, требует чистую ветку `main`, проверяет удалённую ветку, публикует Worker и отправляет код в GitHub. После завершения нужно дождаться успешной сборки Pages. Публикации Cloudflare и GitHub не являются одной транзакцией: ошибка второго этапа оставляет уже опубликованный Worker.

Для изменения только приложения достаточно проверок, коммита и `git push origin main`; обновление Worker выполняется, когда меняется серверная логика или нужен совместный выпуск.

## Cloudflare

Конфигурация перенесена из действующего Dashboard, включая существующее KV-хранилище `SUBS` и расписание раз в минуту. Секреты `GEMINI_KEY` и `VAPID_KEY` остаются в Cloudflare. `keep_vars` сохраняет дополнительные переменные, заданные в Dashboard.

Авторизация сохранена локально и не включена в репозиторий. На другом компьютере потребуется вход в GitHub и Cloudflare:

```powershell
git credential-manager github login --device --no-ui
cd worker
.\node_modules\.bin\wrangler.cmd login --device --browser=false --use-keyring
```

Дальнейшие изменения Worker следует вносить в репозиторий. Если код или настройки изменены через Dashboard, перед следующим выпуском их нужно сверить с локальными файлами.

## ИИ и пищевая ценность

Gemini распознаёт блюдо, количество, марку и состав рецепта, затем выбирает подходящую запись среди результатов разрешённых источников. КБЖУ берутся из полученных данных; арифметику порции и рецепта выполняет Worker. Google Search grounding не используется: отдельная поисковая подписка и API-ключ USDA не нужны. Сохраняется действующий секрет `GEMINI_KEY`.

Источники:

- [Matvaretabellen](https://www.matvaretabellen.no/en/api/) — официальный норвежский справочник для обычных продуктов и ингредиентов. Это не база узбекских готовых блюд; местные блюда считаются по составу, а предполагаемая рецептура явно помечается оценкой.
- [Open Food Facts](https://world.openfoodfacts.org/) — конкретные упакованные товары по марке или штрихкоду. Учитываются полные значения с упаковки/от производителя, единица и состояние продукта. [ODbL](https://opendatacommons.org/licenses/odbl/1-0/). Изображения OFF не используются. Уведомление об источниках доступно в настройках и в окне добавления еды.

При новом добавлении, в том числе через фото, тренера или быстрый повтор, источник запрашивается заново. Старые ответы ИИ не используются как база. Запись дневника хранит снимок КБЖУ и происхождения, поэтому новые сведения не переписывают историю. Изменение только количества уже записанной порции пересчитывается из её исходного снимка; замена еды требует нового поиска. Фото, неизвестная масса и предполагаемый состав дают приблизительную оценку.

Если точного продукта с полными данными нет, источник недоступен или единицы не подходят, приложение просит уточнение либо повторить запрос. Подмена старым ответом, отсутствующих нутриентов нулями или похожим брендом не выполняется. Само обновление источника не гарантирует повышения точности конкретной записи.

Проверки включены в скрипт публикации:

```powershell
node --test scripts/frontend.test.mjs
npm.cmd --prefix worker test
```
