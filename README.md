# Калории

[Открыть приложение](https://kolpakov-uz.github.io/kalorii/)

Статическое приложение для дневника питания. Интерфейс находится в `index.html`, браузерные уведомления — в `sw.js`, серверная логика Gemini и push-уведомлений — в `worker/index.js`.

## Веб и Telegram

Обе версии поддерживаются. Для самостоятельного входа через Safari, другой браузер или установленную иконку один раз получите код кнопкой «Веб-версия» в Telegram-приложении и вставьте его на сайте. Браузер запоминает доступ, прежний дневник сохраняется. [Подключение и модель доступа](docs/telegram.md#самостоятельная-веб-версия).

## Публикация

GitHub Pages автоматически публикует корень ветки `main`. Worker `kalorii-ai` публикуется через Wrangler с конфигурацией `worker/wrangler.jsonc`.

На настроенном компьютере из папки репозитория:

```powershell
npm.cmd --prefix worker ci
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/publish.ps1 -CheckOnly
```

После проверки и коммита изменений:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/publish.ps1
```

Скрипт проверяет исходники, собирает Worker без публикации, требует чистую ветку `main`, проверяет удалённую ветку, публикует Worker и отправляет код в GitHub. После завершения нужно дождаться успешной сборки Pages. Публикации Cloudflare и GitHub не являются одной транзакцией: ошибка второго этапа оставляет уже опубликованный Worker.

Для изменения только приложения достаточно проверок, коммита и `git push origin main`; обновление Worker выполняется, когда меняется серверная логика или нужен совместный выпуск.

## Cloudflare

Конфигурация перенесена из действующего Dashboard, включая существующее KV-хранилище `SUBS` и расписание раз в минуту. Секреты `GEMINI_KEY` и `VAPID_KEY` остаются в Cloudflare. `keep_vars` сохраняет дополнительные переменные, заданные в Dashboard.

Авторизация сохранена локально и не включена в репозиторий. На другом компьютере потребуется вход в GitHub и Cloudflare:

```powershell
git credential-manager github login --device --no-ui
cd worker
.\node_modules\.bin\wrangler.cmd login --device --browser=false --use-keyring
```

Дальнейшие изменения Worker следует вносить в репозиторий. Если код или настройки изменены через Dashboard, перед следующим выпуском их нужно сверить с локальными файлами.

## Модели Gemini

Worker использует очередь `gemini-4-hydrogen` → `gemini-3.8-flash` → `gemini-3.5-flash-lite` для дневника, фото, чата тренера и голоса. Очередь задаётся в `worker/wrangler.jsonc` переменными `MODEL` и `MODEL_FALLBACKS`. Google предлагает бесплатный API-доступ к этим моделям в пределах квот проекта. Фактическая доступность определяется ответом API с действующим ключом.

При исчерпании суточной квоты модель пропускается до следующего календарного дня в `America/Los_Angeles`. Короткие ограничения учитывают `Retry-After` или `RetryInfo`, отказ в доступе к конкретной модели и отсутствие модели проверяются повторно через пять минут. Следующая доступная модель получает исходный запрос с тем же фото или аудио. Сетевые сбои, ошибки сервера и неполные ответы пропускаются на 30 секунд. Если суточные квоты исчерпаны у всей очереди, расчёт приостанавливается.

Схема ответа дневника явно описывает название, вес и все четыре показателя КБЖУ для добавления. Сервер проверяет содержимое успешного HTTP-ответа до выбора модели. При отсутствующих данных, сломанном JSON или обрыве генерации он переходит к следующей модели в том же запросе. Отказ по безопасности остаётся окончательным. Текстовые расчёты используют низкий уровень рассуждения новых моделей, фотографии и тренер — средний. На попытку одной модели отводится до 8 секунд, на серверную очередь — до 24 секунд. Автоповторы запросов дневника и тренера в приложении разделяют общий срок 45 секунд, включая паузы.

Для каждого действия тренера задана отдельная схема с его полями. Это ограничивает сложность схемы для API и делает параметры тренировки обязательными. Разные длительности силовой и кардио записываются отдельными тренировками с общей датой. Сервер проверяет весь ответ до отправки клиенту, клиент проверяет тренировки до применения набора действий. Автоповтор меняет только транспорт и разбор ответа, успешные действия применяются один раз. Регрессии записи через реальный обработчик чата, повторов и отмены входят в `scripts/coach.test.mjs`.

Состояние ограничений хранится в `SUBS` под префиксом `gemini:cooldown:v1:`, отдельно для каждой модели и SHA-256 отпечатка API-ключа. В него записываются только категория ограничения и срок, общие для всех пользователей. Новый запрос после восстановления квоты снова начинает с приоритетной модели. Каждый переход к другой модели создаёт дополнительный вызов API. Проверки очереди и восстановления входят в публикацию, отдельно запускаются командой `node --test scripts/gemini.test.mjs`.

## Голосовой ввод

При временной ошибке сервиса, сети или таймауте запрос повторяется автоматически один раз; при исчерпанной квоте и постоянных ошибках автоматического повтора нет. Между запросами выдерживается не менее 5,2 секунды. Каждый повтор может расходовать квоту Gemini. Если сбой сохраняется, аудио остаётся только в памяти текущего окна, а кнопка «Повторить» продолжает с нераспознанного фрагмента. Успешные части сразу добавляются в редактируемое поле без повторного добавления при следующей попытке. Уведомление упоминает оставшийся текст только при непустом поле. Отмена, новая запись, закрытие панели, смена раздела или уход в фон удаляют сохранённое для повтора аудио.

Микрофон рядом с отправкой доступен в дневнике и чате тренера. Повторное нажатие останавливает запись и запускает расшифровку; результат добавляется к текущему тексту, остаётся редактируемым и не отправляется автоматически. Автоматического ограничения длительности нет. Длинное аудио после остановки разбивается на последовательные WAV-фрагменты до 28 секунд (по возможности на паузах), без обрезки и потери хвоста. Они отправляются последовательно с паузами для соблюдения квоты, тексты собираются по порядку в один черновик. Память устройства, доступность сервиса и квоты Gemini остаются техническими ограничениями. Отмена, закрытие окна, переход между разделами или уход приложения в фон прекращают запись. Требуются HTTPS, разрешение микрофона, MediaRecorder и OfflineAudioContext; формат записи выбирается браузером, затем преобразуется в WAV 16 кГц mono PCM.

`voice.js` управляет записью, звуковым анализатором и черновиком, `worker/voice.js` проверяет WAV-фрагменты и формирует запрос `transcribe` к действующей модели Gemini. Аудио не сохраняется приложением в дневнике или KV; для расшифровки оно передаётся Gemini с действующим ключом. Расшифровка расходует один запрос Gemini на фрагмент, последующая отправка сообщения — ещё один. Волны вокруг круглой кнопки получают амплитуду из RMS сигнала микрофона через Web Audio: в тишине затухают до нуля. Граф анализатора не соединяется с динамиками. При остановке, ошибке или отмене освобождаются треки, AudioContext, таймеры и кадры анимации. При недоступном микрофоне текстовый ввод остаётся доступным. Автотесты: `node --test scripts/voice.test.mjs`; они включены в публикацию.
