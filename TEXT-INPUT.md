# Текст и буфер обмена

В Telegram используются системная клавиатура и нативное выделение в `contenteditable="plaintext-only"`. В браузере сохранён прежний выбор между системной и собственной клавиатурами. Для выделения текста блокировка прокрутки диалога не отменяет жесты редактора и сообщений.

`chat-text.js` добавляет кнопки копирования к текстовым сообщениям дневника и тренера. Копируется содержимое сообщения без иконок и управляющих кнопок, с переносами строк и эмодзи. Для редактора читается `innerText`, чтобы `<br>` и блочные переводы строк не слипались при отправке. Резервный способ копирования восстанавливает фокус и выделение. Если оба способа отказали, показывается ошибка; собственное меню не вырезает текст. Асинхронное вырезание отменяется, если черновик изменился. Длинная вставка не обрезается до 500 символов.

При обновлении переписки переиспользуются неизменившиеся сообщения с устойчивыми ключами. Получение ответа по другой задаче сохраняет выделение и не прокручивает выделенный текст вниз. Данные дневника и серверная авторизация не меняются.

Браузерные проверки входят в `scripts/publish.ps1`. Подготовка из корня репозитория в PowerShell:

```powershell
npm.cmd ci
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location) '.wrangler/browsers'
npx.cmd playwright install chromium webkit
npm.cmd run test:ui
```

Тесты открывают настоящий клиент на локальном сервере в Chromium и WebKit с размером экрана iPhone. Дневник и ответы API синтетические, внешние запросы перехватываются: пользовательский дневник и квота ИИ не затрагиваются. Скриншоты и браузеры находятся в игнорируемой `.wrangler`. Проверяются замена выделенного текста, жесты, сохранение диапазона при новом ответе, копирование, оба отказа буфера, вырезание, гонка изменения черновика, длинная вставка и чат тренера. WebKit-эмуляция не воспроизводит системную панель UIKit и ручки выделения физического iPhone; эти детали требуют проверки на устройстве.
