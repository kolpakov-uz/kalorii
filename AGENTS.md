# Работа с проектом «Калории»

- Репозиторий: `https://github.com/kolpakov-uz/kalorii.git`, основная ветка `main`.
- Приложение: `index.html`, `sw.js`, `manifest.webmanifest`, две PNG-иконки.
- Cloudflare Worker: `worker/index.js`; конфигурация: `worker/wrangler.jsonc`.
- GitHub Pages публикует корень `main` по адресу `https://kolpakov-uz.github.io/kalorii/`.
- API приложения: `https://kalorii-ai.crytime04.workers.dev`.

Пользователь хочет, чтобы при запросе обновления и публикации агент сам обновлял приложение и необходимый код Worker, проверял их и выполнял публикацию обоих компонентов. Ручное копирование кода в Dashboard больше не требуется. Не публикуй изменения при запросе только на изучение или подготовку.

Перед выпуском:

1. Проверь `git status`, актуальность `main` и изменения пользователя. Не перезаписывай чужую работу.
2. При необходимости установи зависимости: `npm.cmd --prefix worker ci`.
3. Выполни `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/publish.ps1 -CheckOnly` и проверки, соответствующие изменённому поведению. Проверка синтаксиса не заменяет проверку поведения интерфейса.
4. Закоммить предназначенные для выпуска изменения. Подпись уже настроена локально на профиль GitHub пользователя.
5. Выполни `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/publish.ps1`. Скрипт сначала проверяет и публикует Worker, затем отправляет `main` в GitHub для публикации Pages.
6. Убедись, что сборка Pages завершилась и опубликован нужный коммит; проверь приложение и затронутые операции API. Обычный GET к Worker ожидаемо возвращает 403. Для проверки без обращения к Gemini можно использовать OPTIONS с Origin `https://kolpakov-uz.github.io` и POST с неизвестным mode: ожидаются CORS и 400 `bad`.

Авторизация GitHub сохранена в Git Credential Manager, Cloudflare — через Wrangler OAuth в зашифрованном файле с ключом в Windows Credential Manager. Доступ зависит от пользователя Windows. В песочнице могут потребоваться разрешения на сеть и доступ к хранилищу учётных данных. При ошибке Git `dubious ownership` используй разовое `git -c safe.directory=<абсолютный путь репозитория>`; не меняй глобальную конфигурацию без необходимости.

Сохраняй существующее KV-хранилище `SUBS`, секреты `GEMINI_KEY` и `VAPID_KEY`, расписание и совместимость API. Не создавай новые VAPID-ключи: публичный ключ уже используется клиентами. В `wrangler.jsonc` перенесены действующие настройки из Dashboard; `keep_vars` сохраняет дополнительные переменные Dashboard. Не меняй MODEL или compatibility_date без необходимости. Значения секретов не помещать в Git или вывод инструментов. Служебный импорт Dashboard и локальные сборки игнорируются Git.

Если Worker опубликован, но push или сборка Pages завершились ошибкой, сообщи о частичном выпуске и исправь оставшийся этап; не объявляй выпуск успешным. Для изменения пользовательских настроек Cloudflare вне задачи обновления требуется отдельное основание.

Пищевая ценность: Gemini остаётся основным интерфейсом, распознаёт текст/фото и выбирает запись источника. Разрешены Matvaretabellen (обычные ингредиенты) и Open Food Facts (марки/штрихкоды); не включай платный Google Search grounding или новые ключи без основания. Числа модели не являются подтверждёнными КБЖУ. Все новые добавления проходят через `food-pipeline.js` и `nutrition.js`, включая чат и быстрый повтор. Противоречащие op/type действий отклоняются; метаданные nutrition от модели удаляются. Нельзя возвращать локальные S.dc/S.foods или предыдущие ответы вместо нового запроса. Историю дневника и снимки nutrition сохранять. Смена массы исторической порции использует её снимок; состав/марка/обработка требуют поиска. Ошибки источника не заменять нулями или несвязанными продуктами.

Не путай официальный справочник ингредиентов с проверенной базой узбекских блюд. Рецепты рассчитываются по массам ингредиентов и выходу готового блюда; предполагаемый состав/масса на фото помечаются оценкой. Граммы и мл не взаимозаменяемы. Лицензионное уведомление доступно через `openSources()` из настроек и окна добавления; пользователь предпочитает отсутствие внешних ссылок возле каждой записи. Тесты поведения фронтенда и Worker обязательны для изменений этой логики и выполняются скриптом публикации.
