# Telegram Mini App

Бот: [@caloriies_ai_bot](https://t.me/caloriies_ai_bot).
Адрес полной версии: `https://kolpakov-uz.github.io/kalorii/`.

В @BotFather выполните `/setmenubutton`, выберите бота и задайте адрес полной версии вместо `keyboard-test.html`. Название кнопки — «Открыть Калории». Для кнопки запуска в профиле настройте Main Mini App на тот же адрес через `/mybots` → Bot Settings → Configure Mini App. Ссылкой `https://t.me/caloriies_ai_bot?startapp` можно пользоваться после включения Main Mini App.

## Поведение

- Один HTML работает в обычном браузере и Telegram. Наличие параметров реального запуска SDK включает адаптацию Telegram; само посещение ссылки в браузере её не включает.
- В Telegram всегда используется системная клавиатура, независимо от сохранённого переключателя собственной клавиатуры. Темы, безопасные отступы, кнопка «Назад» и добавление иконки используют Telegram SDK с проверкой версии. Добавление иконки зависит от поддержки клиента.
- ИИ, фото и голос продолжают обращаться к тому же Worker с той же моделью. Токен бота для этого не нужен.
- В Telegram напоминания появляются только внутри открытого приложения. Фоновые сообщения бота не подключены; для них понадобится отдельная серверная интеграция и секрет токена. Обычная версия сохраняет существующие настройки веб-уведомлений.

## Перенос дневника

В исходном приложении откройте «Настройки» → «Данные» → «Сохранить в файл». На iPhone сохраните JSON в «Файлы». Затем откройте полную версию из кнопки бота: на первом экране выберите «Перенести дневник из файла» или используйте «Настройки» → «Данные» → «Загрузить из файла». После выбора файла приложение покажет число дней и записей и попросит подтвердить замену.

Состояние профиля, записи, вода, замеры, тренировки, цели и история переносятся локально; файл не загружается на сервер. Перед заменой сохраняется копия на устройстве, доступная через «Вернуть данные до переноса». Формат версионирован, входные данные проверяются до записи. При нехватке места импорт останавливается. Лимит файла — 20 МБ.

Браузер использует прежний ключ `kalorii-v1`; Telegram — отдельный ключ с идентификатором аккаунта, чтобы локальные данные разных аккаунтов не смешивались. Это локальное разделение хранилища, а не проверка личности. `initDataUnsafe` используется только для интерфейса и локального ключа. Автоматической синхронизации между устройствами нет.

## Личный доступ

Все POST-запросы Worker, включая голос, фото, чат и настройки подписок, требуют подписанного Telegram `initData` в поле `telegramInitData`. Сервер проверяет HMAC-SHA-256 по секрету `TELEGRAM_BOT_TOKEN`, срок запуска (до 24 часов с допуском 30 секунд для часов) и числовой ID по секрету `TELEGRAM_ALLOWED_IDS`. Последний содержит JSON-массив из одного или двух числовых ID. Имена пользователей и присланные клиентом отдельные ID не являются доказательством входа. Числовые ID не включаются в Git.

На текущем этапе пользователь попросил разрешить только его аккаунт @L0ng_life. Жена (@kamilakomzik) пока не включена; при добавлении её ID нужно сохранить существующий ID владельца в списке.

При отсутствии или ошибке конфигурации доступ закрывается (503); при отсутствии, подмене или истечении подписи — 401; для проверенного постороннего аккаунта — 403. `mode: access` выполняет такую же проверку без обращения к Gemini. Каждый рабочий запрос проверяется независимо от экрана входа. Лимит запросов разделён по проверенному ID. Старые веб-подписки без проверенного владельца остаются в KV, но не используются для отправки уведомлений; новые подписки привязываются к авторизованному ID.

Страница в Safari предлагает выгрузить ранее сохранённый дневник, но серверные функции доступны только при подтверждённом запуске через Telegram. Публичные исходники и статические файлы на GitHub Pages по-прежнему видны; серверная проверка закрывает использование API, а не скрывает HTML/JavaScript или имя бота в поиске. Для сокрытия самих файлов потребуется отдельное закрытое размещение.
